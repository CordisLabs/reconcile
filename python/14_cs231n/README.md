## 论文报告

CS231n 是课程（Karpathy, Li 等），本切片对应的两件事是可核对的算术：

- 卷积输出尺寸：`(W − F + 2P) / S + 1`
- VGG16（配置 D）的参数量：**138,357,544**（约 1.38 亿），13 个卷积层、5 个池化、
  3 个全连接，其中 FC1 一层就占了 1.03 亿

## 本仓实测

15 项检查，0.2 秒。

| 检验 | 实测 |
|---|---|
| im2col 卷积 == 朴素循环卷积（3 组 stride/pad） | max\|Δ\| ≤ **5.3e-15** |
| 1×1 / 3×3 / 5×5 核 | 同样在 1e-12 内 |
| 输出尺寸公式（4 组 k/s/p） | 与实测形状全部一致 |
| max-pool(arange(16), 2×2) | **[5, 7, 13, 15]**，argmax 全为窗口内索引 3 |
| 池化反向路由 | 4 个梯度各自落在 argmax 位置，和为 4 |
| VGG16 参数量 | **138,357,544**（逐层算出，与课程一致） |

## 差异归因

**1. im2col 与朴素卷积不是逐位相等，是 5.3e-15。** 两者的浮点求和顺序不同，结果在
末位上有差异。写"逐元素相等"时必须把容差一起写出来——本仓用 `< 1e-12`，不是 `==`。
把这类比较说成 exact 是同类仓库里很常见的夸大。

**2. 没有训练，没有 CIFAR。** CS231n 的作业包含实际训练与调参；本切片只验证算子语义与
参数计数。所以"卷积写对了"不等于"模型能训"。

**3. VGG16 的 138,357,544 依赖三个约定**：FC1 的输入是 7×7×512、分类数是 1000、每个
全连接都带 bias。任何一个换掉，数字就变。它能对上，恰好说明这三个约定都选对了——
这也意味着这个数字不能脱离约定单独引用。

**4. 池化并列最大值的约定是 `np.argmax` 的第一个。** 课程与论文都没有规定并列时梯度
给谁；这里采用第一个，并在代码里写明。
