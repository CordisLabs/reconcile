# 21 · Relational Recurrent Neural Networks（Santoro et al., 2018）

记忆槽之间用多头点积注意力交互。

> 注：只实现单元与其性质，**没有控制器、没有训练、没有与 LSTM 的任务对比**。

## 论文报告

机制（论文 §2）：维护一小撮 memory slots，每一步让它们通过 MHDPA 交换信息，再各自更新：

```
slots ← slots + MHDPA(slots)
slots ← slots + MLP(slots)
```

论文的主张：这种"槽之间的直接通信"让 RMC 在需要跨步记忆的任务上优于 LSTM。

## 本仓实测

4 项检查，瞬时。

| 检验 | 实测 |
|---|---|
| 每个头的注意力行和 | 1 − **1.1e-16** |
| 权重非负 | ✅ |
| 注意力不是均匀分布（槽确实在交互） | 最大偏离 0.3+ |
| 槽的置换等变性（10 次置换） | **2.2e-16** |
| 单元梯度 vs 有限差分 | **6.4e-10** |

## 与 LSTM 的对比（GPU）

论文的卖点是"槽之间的通信让 RMC 在 LSTM 失败的任务上成功"。这里给这个主张一个数字。

任务：读一个符号序列，在结尾输出**第一个**符号。序列越长，越考验状态保持。

| 序列长度 | LSTM | RMC | 随机基线 |
|---|---|---|---|
| 5 | 1.000 | 1.000 | 0.25 |
| 20 | **0.331** | **1.000** | 0.25 |
| 50 | **0.336** | **1.000** | 0.25 |
| 100 | **0.331** | **1.000** | 0.25 |

LSTM 在长度 ≥20 时**掉到随机水平**（0.33 ≈ 1/3，实际可用符号 3 个），而 RMC 全程 1.000。
两个模型共享同一个 LSTM 控制器、同一个嵌入、同一个输出层，唯一差别是槽的记忆。

**必须说清的简化**：一次性版本注意全序列；逐时间步版本是论文的机制。两者
在长度 20 都成功，但逐时间步版本在长度 50 退化到随机水平——见上一节的表。

## 逐时间步的槽更新（论文的真实机制）

上面那版让槽一次性注意整个序列。这一节实现论文的**逐时间步**更新，并试了三种具体形式：

| 序列长度 | LSTM | RMC 一次性 | 逐时间步（cross） | 逐时间步（居中） | 逐时间步（槽 self-attn） |
|---|---|---|---|---|---|
| 20 | 0.316 | **1.000** | **1.000** | **1.000** | **1.000** |
| 50 | 0.323 | **1.000** | 0.323 | 0.323 | 0.323 |

**三种逐时间步实现都在 L=50 回到随机水平**，而一次性注意全胜。第三种是最接近论文的写法
（槽之间互相注意、当前隐状态作为额外 token），也一样。

**这指向机制本身的性质，而不是某一种写法的 bug**：每步一次残差更新 + LayerNorm，50 步之后
第一个 token 的贡献被摊平；而一次性注意把整个序列保留为 key，不需要"记住"。

**结论**：论文"记忆槽解决 LSTM 做不到的长延迟任务"这条，**在一次性注意的形式下成立**（L=50
仍然 1.000），**在逐时间步的形式下不成立**。这是本仓对机制的一个具体限定，不是对论文的否定——
论文的槽更多（这里 8 个）、更新方式更复杂。

## 差异归因

**1. 与 LSTM 的对比做了，两种 RMC 实现都测了。** 论文的卖点是"在 LSTM 明显失败的
记忆任务上，RMC 能学会"。本切片没有训练任何一个模型，所以**不能**说 RMC 更好。

**2. 没有控制器、没有跨步循环。** 这里只实现了一个单元内的槽更新；论文的 RMC 把槽接在
LSTM 旁边，跨时间步维护。

**3. 置换等变是构造性的**（注意力对槽的顺序天然等变），验证的是实现正确性。

**4. 行和 = 1 是 softmax 的定义**，不是学出来的——和 15/16 一样，要区分"实现正确"和"模型
学会"。
