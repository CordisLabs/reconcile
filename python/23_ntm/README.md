# 23 · Neural Turing Machines（Graves, Wayne, Danihelka, 2014）

可微分外部记忆的**寻址机制**：内容寻址、位置寻址、读、写。

> 注：本切片只实现寻址与记忆操作，没有控制器、没有 BPTT、没有训练 copy 任务。

## 论文报告

机制（论文 §3）：控制器通过"读头 / 写头"操作一个 N×W 的记忆矩阵，寻址权重是一个对行的
概率分布：

```
w_i = softmax(β · cos(K, M_i))                内容寻址
w = sharpen(g·w_prev + (1−g)·shift(w_prev))  位置寻址
M_i ← M_i · (1 − w_i·e) + w_i·a              写
r = Σ_i w_i·M_i                               读
```

论文的核心主张是这套机制**可微**，因此可以用梯度端到端训练，并学会算法（copy、排序）。

## 本仓实测

8 项检查，0.1 秒。

| 检验 | 实测 |
|---|---|
| 内容寻址权重和 | 1.000000000000 |
| 权重非负 | ✅ |
| β = 200 时收敛到最相似行 | max 权重 > 0.999，argmax 与 cosine 一致 |
| 插值门 g = 0 | 逐位复现上一时刻权重（差 < 1e-12） |
| 循环移位（位移 one-hot） | 质量正好移动一格 |
| 均匀权重读 | 等于记忆的行均值 |
| erase = add = 0 的写 | 记忆不变（差 < 1e-15） |
| erase = add = 1 的写 | 被寻址行恰好变成 1，其余不变 |

## copy 任务（GPU）：长度外推

上面的检查都是算子的性质。`gpu/copy_task.py` 补上缺的一半：控制器 + BPTT + 论文的第一个
演示任务，并测**长度外推**。

| 训练 | 步数 | 训练长度 | 长度 8 | 长度 15 | 长度 20 |
|---|---|---|---|---|---|
| 固定长度 5 | 12,000 | **94.6%** | 0% | — | — |
| 混合 3–8 + 数值裁剪 | 10,000 | 85.8% | **16.5%** | — | — |
| 固定长度 10 | 30,000 | 28.1% | — | 0% | 0% |
| 课程 5→8→10，batch 64 | 30,000 | 80.7% | — | 0% | 0% |
| **课程 5→8→10，65,000 步** | 65,000 | **97.58%** | — | **0%** | **0%** |
| **同上，读头改用 content addressing 门控** | 65,000 | **95.39%** | — | **0%** | **0%** |

**结论：两版实现都收敛到 95–98%，两版的外推都是 0%。**

**这不是训练量问题。** 模型在训练长度上几乎满分，到 15 就完全失效——它学到的是**与长度绑定的
策略**，不是"读一个、右移、写一个"的通用算法。

**最后一行排除了一个具体怀疑**：原来的读头用 `g·w_prev + (1−g)·shift(w_prev)`，而论文的公式是
`g·w_content + (1−g)·shift(w_prev)`——少了 content addressing。改成论文的写法之后，训练长度
95.39%，**外推仍然 0%**。所以问题不在这一处寻址细节上。

**这条主张在本仓是未复现，且归因已缩小到**：槽数（这里是少量槽，论文是上百个）、写头的
allocation 机制、以及训练分布（纯课程 vs 混合）。

## 差异归因

**1. 控制器和训练都有了，但没收敛。** 论文的关键是"用梯度学会算法"——copy 任务上训练一个 NTM
并从长度 10 泛化到 20。本切片**完全没有训练**，只验证了寻址算子的性质。

**2. 没有 BPTT 穿过寻址链。** 那需要把 softmax 寻址、写操作、控制器循环全部接入反向传播，
是一个大得多的实现。

**3. 这些性质是构造性的。** 权重和为 1 是 softmax 的定义；g=0 保权重是线性插值的定义。
它们验证的是实现，不是"模型学会了寻址"。

**4. 一条真实发现：β 的作用是锐化，不是选择。** β 再大也只是让分布更尖，argmax 由余弦
相似度决定——这和"内容寻址能精确取到某一行"是两件事。真实 NTM 里 β 由控制器输出，可学习。
